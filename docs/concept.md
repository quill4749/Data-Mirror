# 概念：為什麼需要 Data Mirror？

## 一、看得見，才有選擇

在數位環境裡，我們每天都在留下痕跡：搜尋、導航、按讚、傳訊息、付款、聽音樂。這些動作本身很日常，但它們被記錄、拼接、分析之後，可能描繪出一個比我們想像中更完整的自己。

多數人並非不在意隱私，而是**不知道從哪裡開始在意**。隱私政策太長、權限名稱太技術、資料流向太抽象，於是人們只能憑感覺按下「同意」。Data Mirror 的起點，就是把這道鴻溝縮小：先讓資料收集變得可見，再讓風險變得可理解，最後讓行動變得可行。

## 二、問題不只在單一 App，而在資料鏈

單看一個 App，風險往往不明顯。真正需要被看見的是「資料鏈」：

1. **收集**：App 取得定位、麥克風、通訊錄、剪貼簿或廣告識別碼。
2. **連結**：不同服務透過裝置指紋、登入帳號或第三方 SDK，把行為拼在一起。
3. **推論**：從時間、地點與互動模式推測生活作息、興趣、社交圈與消費能力。
4. **再利用**：資料被用於個人化廣告、內容排序、風險評分，或與合作夥伴共享。

這條鏈的每一段都可能合法、也都可能有其功能目的，但加總起來的影響，往往超出使用者當初按下「允許」時的理解。Data Mirror 不試圖把單一 App 貼上「好」或「壞」的標籤，而是協助使用者看見**整體暴露面**。

## 三、Data Mirror 的三個角色

### 1. 一面鏡子

工具會把使用者選擇的服務，映射成一個「隱私暴露輪廓」：哪些資料類別被收集、程度有多高、哪些因子對總風險貢獻最大。它不是監控工具，而是一面讓使用者看見自己數位足跡的鏡子。

### 2. 一位翻譯

專案把技術語言翻譯成日常語言。例如：

- `ACCESS_FINE_LOCATION` → 「App 可能知道你很精確的位置」
- 第三方廣告 SDK → 「你的行為可能被拿去做跨服務的廣告比對」
- 行為側寫 → 「你的習慣可能被長期記錄，而且很難撤回」

這些翻譯不是為了製造恐懼，而是為了讓討論有共同的語言。

### 3. 一個對話起點

分數不是判決，也不是法律或資安稽核結論。它是一個起點，讓使用者可以和家人、老師、開發者或政策制定者討論：我們願意用多少資料，換取多少便利？哪些收集是必要的？哪些只是「順便」？

## 四、從日常行為到風險分數

Data Mirror 的評估流程分為四步：

1. **選擇服務**：使用者勾選日常使用的 App 或網路服務。
2. **讀取暴露向量**：系統從 `data/service_mapping.json` 讀取每個服務在各種風險因子上的 0／1／2 等級。
3. **計算加權分數**：依因子敏感度加權，得到一個可比較的總分與風險比例。
4. **轉成風險等級**：將連續分數離散化為低、中、高風險，並產生對應的防禦建議。

目前內建的因子包括行為側寫、位置追蹤、精準廣告、麥克風、剪貼簿、通訊錄與生物特徵。這些因子不是寫死在程式裡的固定清單，而是存放在 JSON 的 `risk_factors` 中；新增因子時，模型與介面會自動採用。

## 五、為什麼要加權？

如果每一種資料都一樣重要，分數會失真。取得一次公開天氣資訊，和長期在背景記錄移動路徑，不該被視為同等風險。因此 Data Mirror 使用帶有學理依據的權重：

- **行為側寫（2.0）**：跨 App 長期追蹤會形成持久、難以撤回的個人輪廓，隱私侵害具有不可逆性。
- **位置追蹤（1.5）**：精確與背景定位屬作業系統高敏感權限，可推論住家、工作地與生活作息。
- **精準廣告（1.0）**：第三方 SDK 與 Cookie 支撐商業行銷，但影響範圍通常較前兩者窄。
- **動態因子（1.2–1.8）**：麥克風、剪貼簿、通訊錄、生物特徵等，依其敏感度與不可逆性調整。

加權不是為了製造一個「絕對正確」的分數，而是把「哪一種風險更值得優先處理」這個判斷，變成公開、可調整、可討論的規則。

## 六、為什麼要用決策樹？

加權公式能給出分數，但不易一眼看出「在什麼情況下會被歸類為高風險」。決策樹把這個過程變成可閱讀的規則：先看哪個因子、切在什麼門檻、最後落入哪個類別。

Data Mirror 會將決策樹的文字規則輸出到 `outputs/tree_rules.txt`，並將視覺化圖表輸出到 `outputs/decision_tree.png`。使用者可以檢查模型學到了什麼，而不是只能接受一個黑箱結論。

需要強調的是：決策樹是加權公式的**可解釋近似**。在分類門檻附近，模型與公式可能出現差異；因此介面會同時顯示兩者，並以加權公式與因子明細作為主要判讀依據。

## 七、動態擴充與開源精神

隱私風險會隨技術與法規改變。今天重要的可能是定位，明天可能是螢幕錄製、剪貼簿或穿戴式裝置的生理訊號。若特徵清單寫死在程式裡，工具很快就會過時。

因此 Data Mirror 把因子、權重、說明與建議都放進 JSON，並提供 `register_factor()` 與 `register_service()` 擴充介面。研究者可以調整權重，教師可以加入在地案例，開發者可以接上新的掃描來源，而不需要重寫整個模型。

## 八、無障礙與透明化

隱私教育不應排除任何人。介面使用語意化標題、鍵盤可操作的元件、可見的焦點框、高對比狀態卡，以及文字與圖示並重的風險提示；風險不只靠顏色判斷。決策樹圖片也提供替代文字與可下載的文字規則。

透明化同樣重要：工具會說明公式、門檻、因子權重與資料來源，並明確標示哪些是近似值、哪些是教育性假設。使用者有權知道分數是怎麼來的。

## 九、這不是判決，而是對話的起點

Data Mirror 不會告訴你「這個 App 一定不安全」，也不會取代專業的資安稽核或法律意見。它提供的是一個結構化的視角，幫助使用者：

- 辨識哪些資料類別值得優先關注
- 比較不同服務的相對暴露面
- 理解「加密」不等於「沒有中介資料」
- 知道可以從哪些系統設定開始調整

分數會隨版本、地區、使用者授權與 App 行為而變動。與其追求一次性的正確答案，不如把它當成定期檢視的習慣。

## 十、願景

Data Mirror 希望成為一個可被理解、可被檢查、可被參與的隱私教育工具。當使用者能說出「我知道這個服務收集了什麼、為什麼這需要注意、我可以怎麼做」，數位權利就不再只是抽象口號，而是日常選擇的一部分。

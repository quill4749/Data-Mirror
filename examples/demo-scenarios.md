# 示範情境：把日常使用轉換成可討論的隱私風險

> 本文數字取自目前的 `data/service_mapping.json`。最高可能加權分數為 **21.2**，分類門檻為：
> 低風險 < 33.3%、中風險 33.3%–66.7%、高風險 ≥ 66.7%。
> 實際分數可能隨 App 版本、地區與授權設定而異，以下情境用於教學與討論，不是稽核結論。

## 如何使用這些情境

1. 啟動介面：`streamlit run src/backend/app.py`
2. 在「選擇服務」勾選情境中的 App。
3. 系統會取各服務在每個風險因子上的最高值，作為預設暴露向量。
4. 可在「進階設定」逐項調整因子等級，觀察分數與建議如何改變。

---

## 情境一：社群媒體重度使用者

**人物設定**：每天使用 Instagram 與 TikTok，會看短影音、互動、分享生活，也允許 App 存取定位與麥克風。

**選擇服務**：`instagram`、`tiktok`

**評估結果**

| 項目 | 數值 |
|---|---|
| 加權總分 | 17.8 / 21.2 |
| 風險比例 | 84.0% |
| 風險等級 | ⛔ 高風險 |
| 主要暴露因子 | 行為側寫（4.0）、麥克風（3.6）、位置（3.0） |

**為什麼是高風險**

- 行為側寫與精準廣告都達到「嚴重」：平台可從互動、觀看停留時間與裝置資訊建立長期興趣輪廓。
- 麥克風等級為「嚴重」：若允許背景或非使用期間存取，私人對話與環境聲音可能成為分析素材。
- 位置與通訊錄同時暴露：可推論生活圈、常去地點與社交關係。
- 多項高權重因子同時達到 Critical，使加權比例越過 66.7% 門檻。

**具體防禦建議**

1. 在 iOS 關閉「允許 App 要求追蹤」，Android 重置廣告 ID 並關閉個人化廣告。
2. 將麥克風與定位改為「僅使用期間」，非必要時設為「永不」。
3. 撤銷通訊錄權限；若平台要求上傳聯絡人才能使用，改用網頁版或替代服務。
4. 定期檢視「應用程式與網站存取權」，移除不常使用的第三方登入。

**教學重點**：加密或「只有你看得到內容」不一定等於沒有行為資料。平台仍可能知道你在哪裡、何時使用、對什麼內容停留最久。

## 情境二：通勤族與外送平台

**人物設定**：每天用 Google Maps 導航、叫 Uber，通勤時聽 Spotify。

**選擇服務**：`google_maps`、`uber`、`spotify`

**評估結果**

| 項目 | 數值 |
|---|---|
| 加權總分 | 10.2 / 21.2 |
| 風險比例 | 48.1% |
| 風險等級 | ⚠️ 中風險 |
| 主要暴露因子 | 位置（3.0）、行為側寫（2.0）、精準廣告（2.0） |

**為什麼是中風險**

- 位置追蹤達到「嚴重」：導航與叫車本質上需要精確位置，甚至背景定位。
- 行為側寫與廣告為「中等」或「嚴重」：乘車偏好、常用路線與音樂口味可能被用於推薦或行銷。
- 雖然總分未達高風險，但位置是最高敏感度的權限之一，不能只因總分中等就忽略。

**具體防禦建議**

1. Google Maps 的定位改為「僅使用期間」，並定期清除 Google 定位紀錄。
2. Uber 使用完畢後關閉背景定位；若允許「永遠」存取，應重新檢視。
3. Spotify 關閉個人化廣告或升級無廣告方案，並檢查是否授予不必要的麥克風權限。
4. 在系統設定中檢查「最近存取位置」的 App 清單。

**教學重點**：總分中等不代表每個因子都安全。位置這類高敏感因子即使單獨存在，也值得優先處理。

## 情境三：通訊軟體與社交圖譜

**人物設定**：主要用 WhatsApp 與朋友聯絡，另外安裝 Signal 作為備援；兩者都允許麥克風與通訊錄。

**選擇服務**：`whatsapp`、`signal`

**評估結果**

| 項目 | 數值 |
|---|---|
| 加權總分 | 11.1 / 21.2 |
| 風險比例 | 52.4% |
| 風險等級 | ⚠️ 中風險 |
| 主要暴露因子 | 麥克風（3.6）、通訊錄（2.8）、行為側寫（2.0） |

**為什麼是中風險**

- 兩款通訊軟體都需要麥克風與通訊錄才能提供完整功能，因此暴露面主要來自「功能必要性」而非惡意收集。
- Signal 的廣告與行為側寫分數較低，但通訊錄與麥克風仍屬高敏感資料。
- 加密保護的是訊息內容，不等於保護「誰在什麼時候和誰聯絡」的中介資料。

**具體防禦建議**

1. 僅在通話時授予麥克風權限，並設為「僅使用期間」。
2. 關閉「自動上傳通訊錄」或改用電話號碼邀請；必要時只開放單一聯絡人。
3. 關閉訊息備份到雲端，或為備份設定獨立密碼。
4. 定期檢查連結裝置與登入中的工作階段。

**教學重點**：選擇重視隱私的通訊工具仍有價值，但「端對端加密」只解決部分問題；社交圖譜與使用時間仍是敏感資訊。

## 情境四：財務、生產力與日常工具

**人物設定**：使用行動銀行、Notion 記帳與筆記，另外安裝計算機 App。

**選擇服務**：`mobile_banking`、`notion`、`calculator_app`

**評估結果**

| 項目 | 數值 |
|---|---|
| 加權總分 | 12.3 / 21.2 |
| 風險比例 | 58.0% |
| 風險等級 | ⚠️ 中風險 |
| 主要暴露因子 | 生物特徵（3.4）、行為側寫（2.0）、麥克風（1.8） |

**為什麼是中風險**

- 行動銀行的生物特徵達到「嚴重」：指紋或臉部資料若處理不當，無法像密碼一樣更換。
- 剪貼簿與通訊錄為「中等」：轉帳時複製帳號、接收 OTP，都可能讓剪貼簿成為敏感資料的短暫載體。
- 計算機 App 的風險很低，但仍可能有輕量廣告 SDK；「工具型 App」不等於零風險。

**具體防禦建議**

1. 確認銀行 App 使用裝置本機安全區處理生物辨識，不將臉部或指紋影像上傳雲端。
2. 轉帳或複製 OTP 後，順手清除剪貼簿；避免在不明 App 中貼上敏感內容。
3. Notion 關閉不必要的第三方整合，並檢查分享連結是否公開。
4. 計算機 App 若要求定位、通訊錄或麥克風，應直接拒絕或改用開源替代品。

**教學重點**：風險不只看「App 類型」，也要看它要求哪些權限。銀行 App 的高敏感度是功能所需，但使用者仍可檢查生物辨識的處理方式。

## 情境五：低暴露的日常組合

**人物設定**：只使用計算機與 Notion，沒有社群帳號，也不太使用導航。

**選擇服務**：`calculator_app`、`notion`

**評估結果**

| 項目 | 數值 |
|---|---|
| 加權總分 | 2.2 / 21.2 |
| 風險比例 | 10.4% |
| 風險等級 | ✅ 低風險 |
| 主要暴露因子 | 剪貼簿（1.2）、精準廣告（1.0） |

**為什麼是低風險**

- 沒有行為側寫、位置、麥克風、通訊錄與生物特徵的暴露。
- 分數主要來自輕量廣告 SDK 與剪貼簿讀取，屬於可控的日常風險。
- 低風險不等於零風險：若使用者經常在 Notion 貼上密碼或身份證號，實際影響會比分數更高。

**具體防禦建議**

1. 在系統設定中檢查剪貼簿存取提示，拒絕不明 App 的讀取。
2. 關閉計算機 App 的個人化廣告，或改用無廣告的開源計算機。
3. Notion 的重要頁面啟用兩步驟驗證，避免公開分享連結。
4. 定期備份並檢視帳號的登入裝置。

**教學重點**：風險分數是相對比較工具。低風險的組合仍值得維持良好習慣，而不是從此不再檢視。

## 情境六：動態加入「螢幕錄製」因子

**人物設定**：研究團隊想評估一個新服務，除了原有七個因子，還想加入「螢幕錄製」這個新維度。

**擴充方式**

```python
from service_collector import PrivacyRiskCollector

collector = PrivacyRiskCollector()
collector.register_factor(
    "screen_recording",
    weight=1.6,
    label_zh="螢幕錄製",
    label_en="Screen Recording",
    description="背景錄製螢幕或畫面內容。",
    rationale="可能捕捉訊息、密碼與金融資訊，且難以撤回。",
    advice="撤銷非必要 App 的螢幕錄製與無障礙服務權限。",
)

# 更新既有服務時，先複製完整分數再修改，避免其他因子被歸零。
row = dict(collector.services["instagram"])
row["screen_recording"] = 2
collector.register_service("instagram", row)
collector.generate_mapping_file()
```

**結果**

- 因子數由 7 增至 8，最高可能分數由 21.2 增至 24.4。
- Instagram 的加權總分由 16.0 增至 19.2，風險比例為 78.7%，仍為高風險。
- 重新執行 `python src/backend/tree_model.py` 後，決策樹會自動增加 `screen_recording` 特徵，不需要修改模型程式。
- 重新整理 Streamlit 頁面後，介面會自動出現新的風險因子與建議。

**教學重點**：新增因子會同時改變分子與分母，因此所有服務的風險比例都可能變動。這是動態評分模型的正常現象；若場域需要不同的敏感度，應同步調整 JSON 中的權重與門檻，而不是只改單一服務的分數。

## 情境七：鍵盤與螢幕閱讀器使用者

**人物設定**：使用者無法使用滑鼠，主要以鍵盤操作，並搭配螢幕閱讀器。

**操作流程**

1. 按 `Tab` 跳到「跳至主要內容」連結，按 `Enter` 前往主內容。
2. 使用 `Tab` 移動到服務多選框，輸入關鍵字搜尋並以 `Enter` 選取。
3. 使用方向鍵切換風險因子選項，變更後分數會即時更新。
4. 風險卡會以文字說明等級、分數與百分比，不會只依賴顏色。
5. 決策樹圖片提供替代文字；若不易閱讀，可展開文字規則或下載 `tree_rules.txt`。

**教學重點**：隱私工具若只有視覺化圖表，會排除部分使用者。Data Mirror 將無障礙視為功能的一部分，而不是事後補救。
